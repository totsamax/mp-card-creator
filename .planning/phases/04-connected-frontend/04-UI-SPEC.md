# Phase 4 — UI Design Contract

> Visual and interaction contract for connecting `frontend/PipelineApp.jsx` to the real API.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Scope note:** Phase 4 does NOT redesign visuals. It removes hardcoded mock constants
> (LINES / MASTER_DATA / TEXTS / IMAGES / VIDEO / VERSIONS / ASSEMBLE_TREE) and wires the
> existing components to real API data. This spec therefore LOCKS the existing self-contained
> design system as the contract and adds only the NEW interaction states this phase introduces
> (polling, error state, loading skeletons, empty states, version picker from real manifest).
> Source of all interaction decisions: `04-CONTEXT.md` (D-01 … D-13).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (self-contained inline `STYLES` block in `PipelineApp.jsx`, CSS custom properties on `:root`) |
| Preset | not applicable |
| Component library | none — hand-rolled `.pp-*` classes + inline styles |
| Icon library | `lucide-react` ^0.441.0 (size 12–24, `aria-hidden="true"` on decorative icons) |
| Font | Fraunces (display, `.pp-display`), Inter (body, `.pp-root`), IBM Plex Mono (numeric/code, `.pp-mono`) — loaded via Google Fonts `@import` in `STYLES` |

**Rationale for `Tool: none`:** shadcn gate evaluated and intentionally declined. The project has a
fixed, established design system already living in `PipelineApp.jsx`; CLAUDE.md constraints state
this phase is "purely about connecting UI to real API data — NOT redesigning visual appearance."
Introducing shadcn would violate the phase boundary. No `components.json`, no `tailwind.config`,
no external token files exist — and none are to be added in this phase. Registry safety gate: not
applicable.

## Spacing Scale

The existing UI uses a near-4-point scale via Tailwind utility classes and inline `style` values.
Locked for this phase (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap: 4`), ghost-button padding, badge vertical padding |
| sm | 8px | Inline element gaps (`gap: 2` ladder bars excepted), select chevron offset |
| md | 12px | Card inner padding (`p-3`), stepper button gaps, empty-state vertical gap |
| lg | 16px | Default card padding (`p-4`), main content rhythm (`mb-4`) |
| xl | 20px | Page padding (`p-5`), card form padding |
| 2xl | 24px | Section breaks |
| 3xl | 32px | Layout-level gaps |

Exceptions (pre-existing, NOT introduced this phase — leave as-is):
- Sidebar fixed width `220px`, normalize first column `minWidth: 180px`
- Size-ladder micro-bars `gap: 2px`, bar widths `4–5px` (decorative sparkline, sub-grid by design)
- Input padding `7px 10px`, button padding `8px 14px` (legacy component padding — do not refactor)
- Image-tile grid `minmax(140px, 1fr)`, video grid `minmax(160px, 1fr)`

## Typography

Locked from existing `STYLES`. Sizes in use: 12, 13, and display sizes via `.pp-display`.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px (`text-sm`) | 400 (Inter regular) | 1.5 (annotations use 1.6, pre-existing) |
| Label / meta | 12px (`text-xs`, `.pp-label`) | 500 (Inter medium) | 1.5 |
| Heading | 18–20px (`text-lg` / `text-xl`, `.pp-display`) | 500 (Fraunces medium) | 1.2 |
| Display | 24px (`text-2xl`, `.pp-display`) | 500 (Fraunces medium) | 1.2 |

Weights: regular (400) for body, medium (500) for emphasis/labels/headings. (Fraunces 600 and
Inter 600 are imported but reserved; primary contract is 400 + 500.) Numeric values and codes use
IBM Plex Mono (`.pp-mono`) at the same size as their context with `fontVariantNumeric: tabular-nums`
for status counters.

## Color

Locked from `:root` custom properties. 60 / 30 / 10 split:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--paper #F6F1EA` | App background, image-tile placeholders, button hover surface |
| Secondary (30%) | `#fff` (`.pp-card`) + `--line #E2DACE` borders | Cards, sidebar dividers, table surfaces, inputs |
| Accent (10%) | `--lavender #8E7CC3` (+ `--lavender-soft #ECE7F7`, `--lavender-dark #5B4D96`) | See reserved list below |
| Destructive / error | `--clay #CC7A52` family (`--clay-dark #8C4B2E` for text) | Error state text, "step failed" indicator, validation hints |

Supporting semantic colors (pre-existing, in use this phase):
- `--sage #7E9B7E` family → success/done indicator (`✓`), toast background
- `--muted #948C99` → secondary text, idle step labels, empty-state copy
- `--ink #2B2632` → primary text

Accent (lavender) reserved for: primary CTA buttons (`.pp-btn-primary`), the active sidebar line,
the active stepper tab, the active version-picker focus ring, size badges, and the highlighted "M"
size column. NEVER apply lavender to error, success, or neutral states.

**Error-state color rule (NEW this phase, D-04/D-05):** the `error` step state uses the clay family
exclusively — red symbol `✘` in `--clay` / `--clay-dark` in StepperNav, and error message text in
`--clay-dark`. Do NOT introduce a new red hex; reuse the clay tokens already defined.

## Interaction States (NEW this phase)

These are the contracts Phase 4 adds. Executor implements exactly these; checker validates them.

### Step status indicator (StepperNav, D-03/D-04)
`computeStepStatus` gains state `error`, detected by presence of `manifest.steps[stepId].error`.
`STATE_INDICATOR` gains key `error`:

| State | Symbol | Color | Source |
|-------|--------|-------|--------|
| idle | (none) | `--muted` label | no `manifest.steps[stepId]` |
| running | spinner / `…` glyph, animated | `--lavender` | optimistic after 202, confirmed by poll (D-02) |
| partial | `{done}/{total}` | `--clay` | history incomplete |
| review | `⚠ {done}/{total}` | `--clay-dark` | any `needsReview` |
| done | `✓` (Check icon 12px) | `--sage-dark` | history complete |
| error | `✘` | `--clay` / `--clay-dark` | `manifest.steps[stepId].error` present |

Error takes priority over partial/done when `error` field is present.

### Polling (D-01/D-02)
- After 202 on async steps (`02-texts`, `03-images`): mark step `running` optimistically, then poll
  `GET /lines/:id/manifest` every **5000 ms** while any step is `running`.
- Stop polling when the manifest changes so no step is `running` (done / error / review).
- Always render a manual **"Обновить статус"** button next to the version picker for immediate refresh.
- Polling uses `setInterval` in a `useEffect` keyed on running-step count; clean up on unmount/stop.

### Loading skeleton (Claude's Discretion → resolved)
- While the initial `GET /lines` is in flight: render 3 placeholder sidebar rows using `--line`
  borders on `--paper` blocks (no shimmer library; a static muted block is sufficient and matches
  the calm aesthetic). Once resolved, replace with real lines or the empty state.
- Per-line manifest load: show inline `--muted` text "Загрузка…" inside the active step body until
  `manifests[lineId]` resolves; do not block the whole page.

### Version picker (D-07/D-08)
- Source: `manifest.steps[stepId].history[]`. Remove `VERSIONS` constant.
- Option label format: **`v{N} · {date} · {size_count} разм.`** where `date` = `createdAt` formatted
  ISO → `«20 июн»` via `toLocaleDateString('ru', { day: '2-digit', month: 'short' })`, and
  `size_count` = count of unique `size` values across that version's history entries.
- If `manifest.steps[stepId]` is absent: show "Шаг ещё не запускался" + "Запустить шаг" button
  (existing VersionPicker empty branch — keep).

## Copywriting Contract

All copy in Russian (`response_language: ru`). Locked from CONTEXT.md + Claude's Discretion defaults.

| Element | Copy |
|---------|------|
| Primary CTA (new line) | "Новая линейка" / form submit: "Сохранить и запустить пайплайн" |
| Primary CTA (run step) | "Запустить шаг" (idle step) / "Перегенерировать" (existing version) / "Обновить статус" (manual poll) |
| Primary CTA (retry failed) | "Повторить" |
| Empty state — no lines (D-09) | Heading: "Линеек пока нет." Body + CTA: "Создайте первую →" (button opens QuestionnaireForm) |
| Empty state — step not run (D-08) | "Шаг ещё не запускался" + "Запустить шаг" button |
| Empty state — normalize | "Мастер-данные ещё не созданы. Нажмите «Запустить шаг»." |
| Empty state — texts size | "нет данных" (per-size inline) |
| Empty state — images | "Изображения ещё не генерировались. Нажмите «Перегенерировать»." |
| Empty state — video (D-12) | "Видео: шаг не запущен" (per size; step-04 out of scope) |
| Empty state — excel (D-12) | "Выгрузка не сформирована" (no `05-excel` in manifest) |
| Empty state — assemble (D-13) | Summary of completed steps + versions from manifest; no tree render |
| Error state — step failed (D-05) | Show `manifest.steps[stepId].error` text verbatim, prefixed "Ошибка шага:" + "Повторить" button below |
| Error state — list load failed | "Не удалось загрузить линейки. Проверьте, что сервер запущен, и обновите страницу." |
| Loading | "Загрузка…" (inline, `--muted`) |
| Toast — pipeline started | "Опросник сохранён, пайплайн запущен" |
| Toast — regen started | "Перегенерация запущена — обновится автоматически" |
| Toast — generic error | "Ошибка: {message}" |
| Destructive confirmation | None — Phase 4 has no destructive actions. "Перегенерировать" creates a new version (non-destructive, versioned per CLAUDE.md), so NO confirmation dialog required. |

**Empty/error state replacement rule (UI-01):** No mock fallback. When data is absent, render the
empty/error copy above — never fall back to `LINES` / `TEXTS` / `IMAGES` / `VERSIONS` / `VIDEO` /
`ASSEMBLE_TREE`. Those constants are deleted in this phase.
