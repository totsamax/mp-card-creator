<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API (GET /lines, /manifest, step data) → React DOM | Untrusted/variable server data (mold names, texts, error strings) is rendered into the UI |
| Browser → API base URL | `VITE_API_BASE_URL` determines where fetches go (CORS / origin) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03 | Tampering (XSS) | manifest/text/error data rendered in JSX | mitigate | All rendering uses React JSX text interpolation (`{value}`), which auto-escapes — no `dangerouslySetInnerHTML` is introduced. Image URLs are built from `${size}_${type}.png?version=N` against the same-origin API path, not from raw server HTML. |
| T-04-04 | Denial of service | malformed/empty API response crashing UI state | mitigate | Every view guards with optional chaining (`manifest?.steps?.[id]`) and falls back to empty-state copy; list-load failure sets `listError` instead of throwing; `(data.lines || [])` guards a missing array. |
| T-04-05 | Information disclosure | API base URL / CORS exposure via `VITE_API_BASE_URL` | accept | Single-team internal tool, web-first, no auth (REQUIREMENTS Out of Scope). Default empty base = same-origin; dev proxy already handles `/lines`. No secrets embedded in frontend. |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed (uses existing react, lucide-react, vite). No legitimacy checkpoint required. |
</threat_model>
