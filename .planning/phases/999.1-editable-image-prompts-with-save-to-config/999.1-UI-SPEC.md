# Phase 999.1 — UI Design Contract

> Visual and interaction contract for the per-slide prompt editor added to the 03-images panel. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this phase's UI:** A slide-configuration editor rendered inside the existing `ImageView` component (step 03-images panel), above the "Генерировать изображения" action. Per slide: description input → "Сгенерировать промпт" → editable generated prompt → file attachments → "Сгенерировать изображение". Plus "Добавить слайд" and "Сгенерировать все". No new pages, tabs, or global settings.

**Language:** All user-facing copy is Russian (matches the entire existing UI).

**Design system source of truth:** The mature custom `pp-` token system defined inline in `frontend/PipelineApp.jsx` (lines 34–73). This phase reuses those tokens exactly and introduces NO new colors, fonts, or radii.

## Spacing Scale

Existing system is a 4px base (Tailwind default utilities: `gap-3`=12, `p-3`=12, `p-4`=16). This phase matches it exactly — all values are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, inline chip padding (`py-0.5`) |
| sm | 8px | Button icon gap (`gap: 6px` existing exception), compact field gaps, card inner list gap |
| md | 12px | Grid/list gap between slide cards and between fields (`gap-3`) |
| lg | 16px | Slide card padding (`p-4`), section gap (`gap-4`) |
| xl | 24px | Editor block separation from the image grid below |
| 2xl | 32px | Panel-level top/bottom breathing room |

Exceptions (inherited from existing system, all documented): `6px` border-radius on inputs/buttons; `7px 10px` input padding; `8px 14px` button padding; `6px` button icon gap. Do NOT introduce new off-scale values beyond these existing ones.

## Typography

Faithful to the existing system, which declares three weights (400/500/600) across Inter. New editor UI uses regular (400) for prose, medium (500) for labels/buttons (existing convention), semibold (600) for slide titles.

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Body / input text (description) | 13px | 400 | 1.5 | Inter |
| Generated prompt (technical) | 13px | 400 | 1.5 | IBM Plex Mono |
| Field label | 12px | 500 | 1.4 | Inter |
| Slide title / card heading | 14px | 600 | 1.3 | Inter |
| Helper / meta / muted note | 12px | 400 | 1.5 | Inter (`--muted`) |

Rationale for mono on the generated prompt: it is technical English prompt text (not Russian prose) and mono signals "machine-generated / editable code-like value", consistent with existing `pp-mono` usage for filenames and size codes.

## Color

The existing palette maps cleanly to a 60/30/10 split. No new hex values.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F6F1EA` (`--paper`) | App background, empty image slots, thumbnails behind |
| Secondary (30%) | `#FFFFFF` on `#E2DACE` border (`pp-card` / `--line`) | Slide cards, input fields |
| Accent (10%) | `#8E7CC3` (`--lavender`), soft `#ECE7F7`, dark `#5B4D96` | See reserved list below |
| Destructive | `#8C4B2E` (`--clay-dark`) | Remove-custom-slide action + error text only |

Accent (`--lavender`) reserved for: primary action buttons ("Сгенерировать изображение", "Сгенерировать все"); input focus ring (2px outline); the running/in-progress indicator (`…` glyph); per-size grouping chip background (`--lavender-soft`). NOT used for every button — secondary actions stay neutral `pp-btn` (white/`--line`).

Semantic status colors (reuse existing, do not invent): success = `--sage-dark` `#4F6B4F`; in-progress/running = `--lavender`; warning/needs-review = `--clay`/`--clay-dark`; error/destructive = `--clay-dark`.

## Interaction Contract (phase-specific states)

| State | Trigger | Visual |
|-------|---------|--------|
| Description empty | Slide has no description | "Сгенерировать промпт" disabled; validation copy shown inline in `--clay-dark` on attempt |
| Prompt generating | POST `/slides/:slideId/generate-prompt` in flight | Button label → "Генерирую промпт…", spinner (lucide `Loader2` spin) in button, button disabled |
| Prompt ready | Response received | generatedPrompt textarea filled, becomes editable, "Сгенерировать изображение" enabled |
| Image generating | POST `/slides/:slideId/regenerate` returns 202 | Optimistic running: `…` (`--lavender`) on the slide; polling via existing 5s manifest poll |
| Custom slide only | `default: false` | Show remove (Trash2, `pp-btn-ghost`, `--clay-dark` on hover) — default slides have NO remove control |
| Files attached | putArtifact refs present | Chip list of filenames (`pp-mono text-xs`), each with remove `×` |

Destructive scope: only custom slides (`default: false`) are removable. The 4 default slides cannot be deleted (no destructive affordance rendered). Removal uses an inline confirm (not a full modal), consistent with the app's lightweight interaction style.

Reuse the existing 5s manifest polling loop (`PipelineApp.jsx:816`) and optimistic-running pattern from Phase 04 — do not add a second polling mechanism.
