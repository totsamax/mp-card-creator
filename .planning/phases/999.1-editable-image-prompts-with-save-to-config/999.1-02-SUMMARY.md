# Phase 999.1 Plan 02: Slide-aware step-images Summary

**step-images now sources its generation prompt from the per-article slidesConfig (with on-disk fallback), appends per-size dimensions, handles custom slides without a template read, names artifacts {size}_{slideId}.png, and busts the cache on prompt edits.**

## Accomplishments
- `resolveSlidePrompt(article, slideKey, sizeRecord)` reads `manifest.steps['03-images'].slidesConfig.slides[].generatedPrompt`, falling back to `substitutePrompt` (on-disk `prompts.images.json`) when absent — backward compatible for the four default image types.
- `buildEditRequest` and `generateImage` both build their prompt through the resolve+append path, so actual generation uses the edited per-article prompt.
- `appendSizeDimensions` injects L×W×H + mold size per size so a once-authored prompt stays physically accurate across XS–XL.
- Message shape accepts `slideId`; `slideKey = slideId || imageType`; the guard returns 400 only when both are missing.
- Artifact naming generalised to `${size}_${slideKey}.png`; history entry records both `slideId` and `imageType` (backward-compat).
- `inputHash` now includes the resolved prompt, so editing a slide's `generatedPrompt` invalidates the cache.
- Custom-* slides skip the template-read fallback in `generateImageOpenAI` (throws instead of forming an arbitrary template path — T-999.1-05 mitigation).

## Decisions Made
- Fallback semantics: `resolveSlidePrompt` returns the on-disk default (`substitutePrompt`) whenever there is no slidesConfig or the slide has no non-empty `generatedPrompt`. This preserves backward compatibility for the four default image types and keeps step-images decoupled from Plan 01's `buildDefaultSlides`.
- Custom-slide safety: rather than letting a `custom-*` slideKey form a `templates/{slideKey}.png` path in the images/edits fallback, `generateImageOpenAI` throws for non-default ids (T-999.1-05).
