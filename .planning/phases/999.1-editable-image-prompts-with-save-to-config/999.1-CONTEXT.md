# Phase 999.1: Editable image prompts with save to config - Context

**Gathered:** 2026-07-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Пользователь настраивает набор слайдов для каждой линейки прямо в UI — на панели шага 03-images.
Для каждого слайда: вводит описание (свободный текст, русский) → AI генерирует технический промпт → пользователь видит и может отредактировать промпт → прикладывает произвольные файлы (если нужно) → запускает генерацию изображения.

По умолчанию 4 слайда с предзаполненными описаниями (main, infographic, scale, lifestyle). Пользователь может добавить произвольное число дополнительных слайдов с нуля.
Конфигурация слайдов хранится в YDB как часть данных линейки (per-article) — cloud-совместимо, не зависит от локального файла.

</domain>

<decisions>
## Implementation Decisions

### Расположение в UI (D-01)
- **D-01:** Редактор конфигурации слайдов открывается на панели шага 03-images — контекстно рядом с кнопкой "Генерировать изображения". Не отдельная вкладка, не глобальные настройки.

### Хранение данных (D-02 — D-03)
- **D-02:** Конфигурация слайдов хранится в YDB как часть данных линейки — поле `slides` в манифесте (manifest.steps['03-images'].slides или отдельный документ). Никаких изменений в `prompts.images.json` на диске — файл остаётся как хранилище дефолтов.
- **D-03:** При первой загрузке панели: если slides не задан в YDB — подтягивать defaults из prompts.images.json (4 дефолтных описания + пустые дополнительные). При сохранении — записывать через updateManifest.

### Структура слайда (D-04 — D-06)
- **D-04:** Каждый слайд — объект:
  ```json
  {
    "id": "main" | "infographic" | "scale" | "lifestyle" | "custom-{uuid}",
    "label": "Главное фото",
    "description": "Строка на русском — что должно быть изображено",
    "generatedPrompt": "Technical English prompt — сгенерирован AI из description",
    "files": ["artifact-ref-1", "artifact-ref-2"],
    "default": true | false
  }
  ```
- **D-05:** Первые 4 слайда — default: true, id = 'main'/'infographic'/'scale'/'lifestyle', предзаполненные description из prompts.images.json. Дополнительные — default: false, id = 'custom-{uuid}', description пустое.
- **D-06:** feedbackSuffix остаётся редактируемым (как и в варианте 3 из обсуждения) — хранится на уровне слайда или линейки.

### Цикл на слайд (D-07 — D-08)
- **D-07:** Описание (пользователь вводит) → кнопка "Сгенерировать промпт" → AI call (отдельный LLM-запрос: system — "ты пишешь промпты для DALL-E/gpt-image-2", user — description) → generatedPrompt заполняется в поле рядом. Пользователь может редактировать generatedPrompt вручную.
- **D-08:** После того как generatedPrompt заполнен и файлы прикреплены — кнопка "Сгенерировать изображение" для этого слайда. Либо "Сгенерировать все" для запуска всего набора.

### Файлы (D-09)
- **D-09:** К каждому слайду прикладываются произвольные файлы (фото, шаблоны, референсы). Файлы сохраняются через versionStore.putArtifact в YDB/S3 под ключом `{article}/03-images/slide-files/{slideId}/{filename}`. В поле slides[] хранятся storage refs (не base64).

### API (D-10 — D-11)
- **D-10:** Новый маршрут: `GET/PUT /lines/:id/slides` — читает/записывает конфигурацию слайдов из манифеста. Или интегрировать в manifest-endpoint.
- **D-11:** `POST /lines/:id/slides/:slideId/generate-prompt` — принимает description, возвращает generatedPrompt (LLM call inline, синхронно).
- **D-12:** `POST /lines/:id/slides/:slideId/regenerate` — запускает генерацию одного изображения для слайда; остальные шаги не трогает.

### Claude's Discretion
- Конкретный формат хранения slides в манифесте: как поле manifest.slides или как manifest.steps['03-images'].slidesConfig — на усмотрение планировщика, главное — в YDB.
- LLM-модель для "generate-prompt": достаточно gpt-4o-mini, запрос короткий.
- UX расположения кнопок на панели: "Добавить слайд" / порядок / drag-to-reorder — на усмотрение исполнителя.
- Валидация: минимальная (description непустое перед запросом промпта).

</decisions>

<specifics>
## Specific Ideas

- **Дефолтные описания (4 слайда):** human-readable версии текущих промптов. Например: infographic = "Инфографика с фото молда на фоне шаблона, с размерами и названием молда"; lifestyle = "Лайфстайл с молдом в окружении материалов для творчества".
- **Генерация промпта:** LLM-запрос: system = "You write concise image generation prompts for gpt-image-2 API for product marketplace slides. Output only the prompt, no explanation. Language: English."; user = description + контекст из sizeRecord (moldName, color, moldSize и т.д.).
- **Кнопка "Добавить слайд"** — в конце списка слайдов, добавляет пустой custom слайд с пустым description и generatedPrompt.
- **Редактируемые поля:** description (textarea, ~3 строки), generatedPrompt (textarea, ~5 строк, readonly пока не сгенерирован, редактируемый после).
- **Кнопки:** "Сгенерировать промпт" (рядом с description), "Сгенерировать изображение" / "Сгенерировать все" (рядом с generatedPrompt).

</specifics>

<deferred>
## Deferred Ideas

- Drag-to-reorder слайдов — удобно, но не блокирует MVP; отдельная задача
- Preview сгенерированного изображения прямо в редакторе (текущий ImageView уже показывает его, интеграция в редактор — отдельно)
- Версионирование конфигурации слайдов (history изменений slides) — MVP не требует, достаточно текущего состояния
- Глобальные настройки промптов (не per-article) — пользователь решил, что промпт часть линейки; если понадобятся шаблоны — отдельная фаза
