# Phase 999.1 Plan 03: Editable Image-Prompt Slide Editor (Frontend) Summary

**A per-line slide-configuration editor on the 03-images panel: describe each slide, generate and hand-edit its prompt, add/remove custom slides, attach reference files, save the whole config, and trigger per-slide or bulk image generation — with a slide-driven result grid that displays custom-slide images.**

## Performance

- **Duration:** ~20 min
- **Completed:** 2026-07-03
- **Tasks:** 2 auto tasks executed + 1 human-verify checkpoint (pending)
- **Files modified:** 1 (`frontend/PipelineApp.jsx`)

## Accomplishments
- New "Слайды карточки" section rendered inside `ImagesView`, above the image grid (D-01), loading the per-line config via `GET /lines/:id/slides` (seeded defaults on first open, D-03) with a cancel-guarded effect keyed on `line.id`.
- Per slide: "Описание слайда" textarea → "Сгенерировать промпт" (`Loader2` spinner + "Генерирую промпт…" busy state, empty-description validation in `--clay-dark`) → "Промпт для генерации (можно править)" mono textarea, readonly+muted until a prompt exists then editable (D-07).
- "Добавить слайд" appends a `custom-<uuid>` slide; custom slides render a `Trash2` remove control with an inline confirm; the 4 default slides render no remove affordance (D-05). Section-level editable `feedbackSuffix` (D-06). "Сохранить" persists the whole config via `POST /slides` with the "Конфигурация слайдов сохранена" toast.
- Per-slide file attach via a hidden multipart input → `POST /slides/:id/files` (raw `FormData`, no manual Content-Type), returned refs render as `pp-mono` filename chips each with a removable `×` (D-09).
- Per-slide "Сгенерировать изображение" and section-level "Сгенерировать все" persist the config first, then `POST /slides/:id/regenerate`, set the optimistic images-running flag, and rely on the existing 5s manifest poll — no second interval added (D-08).
- Result grid now iterates the loaded `slides` list keyed on `{size}_{slideId}.png`, with the `done` map built on `h.slideId || h.imageType`, so both default and custom slides display (Plan 02 naming). The `needsReview` badge and empty-state behavior are preserved.

## Decisions Made
- File-attach uses a `<label>`-wrapped hidden `<input type="file">` (accessible, avoids `useRef`), styled as a ghost button with `aria-label="Прикрепить файлы"`.
- Per-slide image generation fans out to all 5 sizes (the Plan 01 route already maps over sizes); the grid's per-item `RotateCcw` reuses the same per-slide regenerate route with `aria-label="Перегенерировать изображение"`.
- `persistConfig()` runs before every generation so `step-images` reads the just-edited prompts.
