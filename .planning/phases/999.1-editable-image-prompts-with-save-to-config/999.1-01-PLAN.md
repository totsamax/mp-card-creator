<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → API router | Untrusted `article`, `slideId`, `description`, and uploaded file bytes cross here |
| API router → LLM (chat/completions) | User `description` is sent as untrusted content in a fixed-system-prompt request |
| API router → versionStore (putArtifact key) | `slideId`/filename become storage path segments |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-999.1-01 | Tampering | putArtifact key from slideId/filename | mitigate | Validate slideId `/^[a-zA-Z0-9_-]{1,64}$/`; sanitize filename with `path.basename(...).replace(/[^a-zA-Z0-9._-]/g,'_')` before the store call |
| T-999.1-02 | DoS | slide-file upload | mitigate | Reuse busboy limits (15 MB/file, 10 files); serve unknown extensions as application/octet-stream (never inline-executable) via existing handleGetArtifact |
| T-999.1-03 | Tampering/Info-disclosure | generate-prompt LLM call | mitigate | Fixed system prompt; treat description as untrusted user-role content; output is a prompt the user reviews before generation, never executed as code |
| T-999.1-04 | Info-disclosure | error responses | accept | respond() returns err.message; internal single-team tool, no auth by design (REQUIREMENTS.md out-of-scope) |
</threat_model>
