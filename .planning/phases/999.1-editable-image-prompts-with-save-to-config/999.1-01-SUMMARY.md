# Phase 999.1 Plan 01: Editable Image-Prompt Slide Backend Summary

**Per-article slide-configuration API: seeded defaults from prompts.images.json, whole-config persistence in the manifest, offline-safe LLM prompt generation, single-slide regenerate enqueue, and arbitrary reference-file uploads with retrievable refs.**

## Accomplishments
- Five new slide routes on `functions/api/index.js` (GET/POST /slides + generate-prompt / regenerate / files), all backed by the manifest store with cloud-fallback.
- `buildDefaultSlides` seeds 4 defaults (main/infographic/scale/lifestyle) from a new RU `descriptions` map in `prompts.images.json`; POST persists and GET round-trips the whole slides array exactly.

- Slide-file upload stores arbitrary reference blobs under the `slide-files` pseudo-step and records a retrievable ref on the slide's `files[]`.
- `test/slides.test.js` fully green (7/7): D-03, D-10, D-11 (stub + 400), D-12, D-09, and slideId path-traversal validation.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Artifact route rejected nested slide-files keys**
- **Found during:** Task 3 (slide-file upload — D-09 GET-on-ref assertion)
- **Issue:** The plan specifies blob key `{slideId}/{filename}` and a ref path containing a slash, but the existing artifact route matcher name group `([^/]+)` cannot match a name containing `/`, so GET on the returned ref would 404.
- **Fix:** Broadened the name group to `(.+)` and added `decodeURIComponent` on the captured name (no-op for existing slash-free names; broadening only matches more paths, never fewer — no regression to existing artifact retrieval).
- **Files modified:** functions/api/index.js
- **Verification:** D-09 `GET on the ref path returns 200` passes; step-images artifact retrieval unaffected.
- **Committed in:** 0e1ac51 (Task 3 commit)

**2. [Rule 3 - Blocking] Uploaded slide blobs were not retrievable (missing manifest step)**
- **Found during:** Task 3 (slide-file upload — D-09)
- **Issue:** `store.putArtifact` does not touch the manifest, and `handleGetArtifact` 404s when `manifest.steps[stepId]` is absent — so `slide-files` blobs could never be served.
- **Fix:** Register the pseudo-step with `store.updateManifest(article, 'slide-files', { currentVersion: 1 })` after upload so `handleGetArtifact` resolves the blob at v1.
- **Files modified:** functions/api/index.js
- **Verification:** D-09 ref retrieval returns 200.
- **Committed in:** 0e1ac51 (Task 3 commit)

**3. [Rule 1 - Bug] Non-hermetic slide test suite**
- **Found during:** Task 3 (running the full suite; D-10 reported "got 8" slides)
- **Issue:** The suite reuses fixed article ids and `tmp-output` persists across runs; the D-10 round-trip test reads the current config and appends, so re-runs grew the stored array and broke the count assertion.
- **Fix:** Clear `OUTPUT_DIR` (tmp-output) once at test-module load so every run starts from a clean baseline. Assertions unchanged.
- **Files modified:** test/slides.test.js
- **Verification:** D-10 passes deterministically across repeated runs.
- **Committed in:** 0e1ac51 (Task 3 commit)
